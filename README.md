# Инвентаризация бара

Локальное приложение для пересчёта остатков алкоголя. Работает как сайт, данные
хранятся только на устройстве (localStorage) — никакой связи с бухгалтерией и серверами.
Код написан так, чтобы без переделок упаковаться в Android-приложение через Capacitor.

## Запуск

```bash
npm install
npm run dev     # http://localhost:5173
npm run build   # готовая сборка в dist/
```

## Как считать

1. **Главная** — разделы (вино, виски, джин…). Нажатие на раздел начинает новый
   пересчёт, если он ещё не начат.
2. Слева на экране подсчёта — **лента всех разделов**: один тап переключает раздел,
   у каждого видно «посчитано / всего». На телефоне это узкая колонка с иконками,
   на широком экране разворачивается в список с названиями.
3. В разделе раскрываешь позицию и вводишь для каждой **точки подсчёта**
   (склад, бар, …). Вид полей зависит от того, как считается позиция:
   - **бутылки + мл** (весь разливной алкоголь, сиропы, соки в литрах):
     «Полных, шт» кнопками − / + и список **открытых** бутылок с остатком в мл.
     Кнопки `¼ ½ ¾ полная` подставляют долю от объёма бутылки, открытых может быть несколько;
   - **штуки** (бутылочное пиво, вода, банки) — одно поле «Количество, шт»;
   - **граммы** (кофе, чай, какао, специи) — одно поле «Вес, г».
   - «Нет в наличии (0)» помечает позицию посчитанной с нулём.
4. Сайт сам считает: полные бутылки × объём + остатки = всего мл / л и
   «эквивалент бутылок» (2 полных + 350 мл из 700 = 2,5).
5. **Итоги и отправка** — сводка по разделам, таблица по позициям, кнопка
   «Завершить пересчёт».
6. **История** — все пересчёты по дате и времени, с полными данными и повторным экспортом.

Каждый пересчёт хранит **снимок справочника** на момент старта: переименование или
удаление позиции потом не портит старые отчёты.

## Журнал и остатки

- **Журнал** — списания по разделам `Кухня / Персонал / Комплимент / Амина / Порча` (список в `src/config.ts`).
  В записи: что, сколько (мл / бутылки / шт / г), кто взял, комментарий. Можно записать и товар вне
  справочника — он попадёт в отчёт, но не в остатки.
- **Остатки** = итог последнего завершённого пересчёта − списания после него. Приходы и продажи не учитываются.
- В Excel-отчёт списания идут в самый конец листа «Инвентаризация», по разделам. Период — от завершения
  прошлого пересчёта до завершения этого; список фиксируется в момент завершения, поэтому правки журнала
  потом не меняют уже готовые отчёты.

## Отчёт

Справочник и формат отчёта перенесены из файла `инвентаризация_2026-16-06.xlsx`.
В книге четыре листа:

| Лист | Что внутри |
| --- | --- |
| **Инвентаризация** | `Наименование товара · Обозначение товара · Ед. · Остаток`. Перед каждым разделом пустая строка-отступ, сам раздел — строка в CAPS, залитая своим цветом |
| **Детализация** | из чего сложился остаток: полные и открытые бутылки, объём бутылки, литры, эквивалент бутылок |
| **По разделам** | свод по разделам |
| **Инфо** | бар, дата, кто считал, комментарий |

Колонка «Остаток» — сумма по всем точкам подсчёта в единице позиции (мл, шт или г).
**Разбивка по складу и бару в отчёт не попадает** — она нужна только при вводе, в приложении.
Итоговых строк в конце листа нет, общие цифры живут на листе «По разделам».

Цвет раздела задаётся в `src/lib/colors.ts` и хранится в самом разделе (`Category.color`),
поэтому в отчёте и в приложении разделы покрашены одинаково. За стили в .xlsx отвечает
`xlsx-js-style` — обычный `xlsx` заливку не пишет.

## Отправка отчёта

Кнопка «Excel → поделиться» формирует `.xlsx` и:

- на Android / в собранном приложении открывает системное меню «Поделиться» —
  оттуда файл уходит в Telegram, на почту, в облако;
- на компьютере (где Web Share API нет) просто скачивает файл.

Если позже захочется отправлять **напрямую в Telegram без шторки** — нужен бот:
`POST https://api.telegram.org/bot<TOKEN>/sendDocument` с `chat_id` и файлом.
Токен придётся хранить в приложении, поэтому так делают только для своего бара.
Отправка на почту прямо из приложения требует внешнего сервиса (EmailJS/свой бэкенд) —
поэтому по умолчанию используется «Поделиться».

## Сервер истории пересчётов

Папка `server/`: маленький сервер на Node без зависимостей. Хранит каждый завершённый пересчёт отдельным
JSON-файлом (прежние версии перезаписанных пересчётов сохраняются), копию справочника и журнала, ежедневно
архивирует данные на сервере (30 дней).

**Установка** (Ubuntu/Debian VDS, под root; IP подставить свой):

```bash
curl -fsSL https://raw.githubusercontent.com/slark4pos/invent/main/server/install.sh | bash -s -- 157.228.190.62
```

Скрипт ставит Node и Caddy, настраивает HTTPS на бесплатном адресе `<ip-через-дефисы>.sslip.io`, службу `mimino`,
файрвол (SSH, 80, 443) и в конце печатает адрес и **ключ доступа**. Повторный запуск обновляет сервер, ключ и данные сохраняются.

**В приложении:** Настройки → «Сервер»: адрес и ключ. Дальше каждый завершённый пересчёт уходит сам,
без связи ждёт в очереди. «Загрузить историю с сервера» возвращает пересчёты на новое устройство,
«Восстановить справочник и журнал» — справочник и списания. Пересчёты, удалённые в приложении, на сервере остаются.

Полезные команды на сервере: `systemctl status mimino`, `journalctl -u mimino -n 50`, `cat /etc/mimino/server.env` (ключ),
данные: `/var/lib/mimino`, архивы: `/var/backups/mimino`.

## Android-приложение (Capacitor)

Android-проект уже создан в папке `android/` (id `com.mimino.inventory`, название «Инвентаризация Мимино»,
иконка — бокал вина). Свободный поворот экрана, учтены вырезы и статус-бар, на планшете в ландшафте
позиции раскладываются в две колонки.

### Как получить APK через GitHub (ничего ставить на компьютер не нужно)

Репозиторий: `slark4pos/invent`. Каждый пуш в `main` запускает workflow `.github/workflows/android-apk.yml`,
который собирает **подписанный** APK и выкладывает его в **Releases**.

- Свежая версия всегда по одной ссылке:
  `https://github.com/slark4pos/invent/releases/latest/download/mimino-inventory.apk`
- Перенести APK на планшет (или открыть ссылку прямо на нём), разрешить установку из этого источника.
- Новая версия ставится **поверх** старой, данные сохраняются.

**Подпись.** Обновление поверх возможно только если подпись всегда одна и та же. Для этого ключ
`mimino-inventory.jks` хранится в секретах репозитория (`ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, alias `mimino`) и подставляется при каждой сборке.
**Файл ключа и пароль нужно хранить отдельно в надёжном месте**: без них приложение на планшете
можно только переустановить, потеряв данные. Номер версии (`versionCode`) берётся из номера запуска
сборки, поэтому только растёт.

Сборка Google Play потребовала бы отдельной настройки — для одного планшета не нужна.

### Если менять код

```bash
npm run build          # собрать веб-часть
npx cap sync android   # перенести в Android-проект
npx cap open android   # открыть в Android Studio (если она установлена)
```

Иконки перерисовываются так:

```bash
node assets/make-icons.mjs
npx capacitor-assets generate --android --iconBackgroundColor '#14110f' --iconBackgroundColorDark '#14110f' --splashBackgroundColor '#14110f' --splashBackgroundColorDark '#14110f'
```

Что важно знать:

- **Данные лежат в памяти приложения.** Удаление приложения с планшета стирает базу —
  перед этим сделайте резервную копию в «Настройках».
- `appId` (`com.mimino.inventory`) нельзя менять после установки: Android посчитает это другим приложением.
- В приложении нет скачивания по ссылке, поэтому и отчёт, и резервная копия уходят через системное
  меню «Поделиться» (Telegram, почта, «Сохранить на устройство»).
- Название заведения («Хинкали Вино Мимино») задано в `src/config.ts`.

## Структура

```
src/
  types.ts            модель данных
  config.ts           название заведения
  data/seed.ts        справочник бара (139 позиций из прошлой инвентаризации)
  lib/store.ts        хранилище localStorage + все действия
  lib/calc.ts         подсчёт бутылок, мл/шт/г, литров, прогресса
  lib/excel.ts        генерация .xlsx в формате прошлых инвентаризаций
  lib/share.ts        «Поделиться» (в Android — нативное меню) / скачивание
  components/         Screen, TabBar, Toast, ProductCard, NumInput
  pages/              Home, CategoryCount, SessionView, History, Catalog, Settings
```

Резервная копия всей базы (`.json`) — в «Настройках», там же сброс к тестовым данным.
